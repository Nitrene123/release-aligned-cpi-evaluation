# Independent information-leakage injection benchmark: design

The benchmark must generate the ground-truth injection log separately from the audited program. Evaluate clean controls and five independently injected violations: late release, unavailable vintage, future lag source, inconsistent target mapping, and differing model-origin samples. Measure detection and false alarms at the case level, and separately whether the reported diagnostic identifies the affected record. Recompute prediction input hashes after deliberate data changes so a generic hash mismatch does not stand in for semantic detection. Use both obvious and boundary cases, and report exceptions and missing metadata separately.

Compare the actual RAE audit implementation against a documented, executable comparison on the same cases. Scikit-learn TimeSeriesSplit is an actual chronological splitter, not an input-vintage auditor: if used, restrict its interpretation to its documented split check. A release-time-only checker implemented for the experiment must be labeled as such, not as an existing third-party audit system. Results on synthetic data are not proof of performance on real archives, and provide no evidence for predictive MAE gains.

The run uses an independent case generator and predeclared expected-fault manifest, with 50 clean controls and 20 cases per violation class. Forecast fingerprints are recomputed after mutations, so the semantic tests do not reduce to stale-hash detection. The comparison is a small structural validator (forecast key, horizon mapping, and common-origin checks) plus scikit-learn `TimeSeriesSplit`'s chronological split-order property. Neither comparator is a full PIT metadata auditor; their scope is stated explicitly.

Interpretation: these synthetic cases test this implementation's behavior on the listed schemas. They do not estimate detection rates on naturally occurring archives, validate all possible data vendors/formats, establish predictive error gains, or prove novelty against every existing software product. The benchmark should remain a technical validation result until expanded with independently sourced natural anomaly cases and a named competing PIT tool that supports the same metadata contract.
